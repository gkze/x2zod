# Compiler Test Contracts

The pinned JSON Schema required suite proves acceptance and value preservation for its cases.
Compiler product contracts have separate evidence. All tests below run through
`bun --no-env-file run check`, which is also required by CI and the release workflow.

| Contract            | Source types      | Declarations | Runtime         | Packed |
| ------------------- | ----------------- | ------------ | --------------- | ------ |
| Required suite      | Emit              | Emit         | All cases       | No     |
| Inference/catchalls | Positive/negative | Consumer     | Yes             | No     |
| Recursive exports   | Positive/negative | Consumer     | Both modes      | No     |
| Codecs/own keys     | Input/output      | Consumer     | Both directions | No     |
| Width/depth         | Leaf/field types  | Consumer     | Yes             | No     |
| Public packages     | Positive/negative | Consumer     | Both modes      | Yes    |

Evidence and ownership:

- `official-suite/conformance.test.ts`: all 3,485 pinned cases, generated acceptance, deep value
  equality and declaration emission. Optional capabilities are separate.
- `runtime-inference.test.ts` and `catchall-declarations.test.ts`: positive assignments and negative
  assertions reject erased fields and widened types. Consumers check source and emitted declarations
  without `skipLibCheck`.
- `exported-reference-runtime.test.ts` and `consumer-equivalence.test.ts`: root/export contracts and
  recursive resources across registration order, inert metadata and runtime modes. Dynamic callers
  may intentionally differ from independent exports.
- `packages/core/test/source-contracts.test.ts`, `consumer-equivalence.test.ts` and
  `catchall-declarations.test.ts`: nested, catchall and recursive transforms; encoded/decoded types;
  both codec directions and own prototype keys. Conformance intentionally disables transforms.
- `test/generated-consumer.ts`: shared strict compiler invocation for core and fixture harnesses,
  including unused bindings, indexed access, exact optional properties and index signatures.
  Declaration consumers resolve emitted modules. Generated inference does not promise
  `isolatedDeclarations`.
- `large-catalog-runtime.test.ts` and `deep-reference-consumer.test.ts`: 33 branches cross the wide
  composition boundary in both modes. A 24-level finite chain checks expansion separately from
  recursive aliases. Runtime values and leaf types are asserted.
- `packed-consumer.test.ts`: actual Bun-packed core, input plugin and runtime manifests/payloads,
  isolated public API generation, source/declaration consumers and runtime checks after removing
  compiler packages.
- `packages/config/test/options.test.ts`, `apps/cli/test/cli.test.ts`,
  `packages/eslint-plugins/test/rules.test.ts` and
  `packages/build-inputs/src/installed-package.test.ts`: option effects, CLI calls, semantic autofix
  boundaries and installed build tooling.
- `package-json.e2e.test.ts`, `meta-schema.e2e.test.ts`, `targets.e2e.test.ts` and
  `opencode.e2e.test.ts`: pinned manifests, meta-schemas, Mise and OpenCode. Application-specific
  catalogs remain owned by downstream consumers.

Unqualified test paths in the table are under `packages/input-json-schema/test`.

## Execution Budget

The fixture harness bounds each Node compilation at 60 seconds and each TypeScript invocation at 15
seconds. Width/depth tests report generated byte size, compilation time, and declaration-check time.
These measurements are diagnostics, not comparative performance claims. The 33-branch catalog must
remain below 1 MiB per mode; its initial observed sizes were approximately 750 KiB inline and 265
KiB shared on the pinned toolchain. Review changes to this ceiling with the generated artifact and
the cause of growth. Do not raise timeouts to conceal algorithmic regressions.

The packed test bounds its subprocesses at 30 seconds. It uses the already installed,
lockfile-pinned third-party dependencies without network installation; only x2zod package payloads
are packed and extracted. It does not establish registry acceptance, dependency installation from an
empty cache, JSR publishing permissions, or compatibility with every downstream toolchain. The
generated runtime is also covered by the existing compiler-free isolation tests.

## Adding Protection

For a regression, identify the failed contract and add the cheapest test that falsifies it. Check
whether the same invariant crosses another public boundary: exports, references, transforms, runtime
mode, declarations, or package payload. Add targeted combinations with fixed expected values and
types; do not multiply every fixture by every option. An equivalence test must still have an
independent expected result so two equally broken variants cannot pass.

Keep semantic cases in the owning plugin or core package. Share compiler invocation and consumer
assurance policy in the native test harness; do not put JSON Schema semantics into core. Preserve
one source of helper generation for inline and shared runtime artifacts.
